NewFileCreator: Die Neue-Datei-Funktion, die macOS fehlt

Tom Jansen · 22.06.2026 · 4 Min. Lesezeit

Auf GitHub ansehen →

Es gibt im Finder eine Lücke, die mich seit Jahren nervt: Per Rechtsklick kann ich einen neuen Ordner anlegen, aber keine leere Datei. Für eine schnelle Notiz, eine todo.md oder eine kleine Konfigurationsdatei öffnet man dann irgendeinen Editor, speichert die Datei und sucht den richtigen Ordner. Oder man nimmt das Terminal. Beides geht natürlich, aber für so einen normalen Arbeitsschritt ist es einfach zu umständlich.

NewFileCreator macht genau diesen Schritt direkt im Finder. Das Tool ergänzt einen „New File“-Eintrag im Kontextmenü. Darunter liegen aktuell zwei Dateitypen, die ich ständig brauche: Text und Markdown. Wenn Untitled.txt schon existiert, wird automatisch Untitled 1.txt daraus. Nicht spektakulär. Aber es ist eine Unterbrechung weniger.

Was man als Nutzer merkt

Der Ablauf soll möglichst banal sein: In einen Ordner rechtsklicken, New File wählen, Dateityp auswählen, fertig. Die Datei liegt direkt dort und ist im Finder ausgewählt. Man kann sie also sofort umbenennen oder öffnen, statt erst in einem Editor einen Speicherdialog zu bedienen.

Für mich sind die globalen Tastenkürzel fast noch wichtiger. Sie funktionieren auch dort, wo der Kontextmenüeintrag nicht greift, zum Beispiel auf dem Schreibtisch. Ich drücke den Shortcut, und die neue Datei landet in dem Ordner, den der Finder gerade als Ziel hat.

Eine Datei anlegen, direkt dort, wo der Finder gerade ist. Mehr muss NewFileCreator nicht können.

Warum dafür überhaupt ein Tool nötig ist

Eigentlich klingt das nach einer Finder-Einstellung, die Apple einfach vergessen hat. Technisch ist es etwas weniger direkt. Der Finder lässt sich nicht beliebig erweitern, und macOS begrenzt, wo Apps schreiben dürfen. Deshalb braucht NewFileCreator eine Finder-Erweiterung und eine App, die den eigentlichen Schritt erledigt.

Für den Nutzer soll diese Aufteilung aber möglichst unsichtbar bleiben. Man klickt im Finder auf New File, wählt Text oder Markdown, und die Datei ist da.

Installation

Für die lokale Nutzung braucht man macOS 14.0 oder neuer und Xcode 15 oder neuer. Danach reichen zwei Befehle: 

make build
make install-local

Das Makefile baut die App und richtet sie lokal so ein, dass der Eintrag im Finder auftaucht. Die einzelnen Schritte sind im Repo dokumentiert. Nach der Installation sollte es reichen, ein Finder-Fenster zu öffnen, in einen Ordner rechtszuklicken und New File auszuwählen.

Was macOS trotzdem vorgibt

Zwei Dinge bleiben sichtbar. Erstens muss man die Finder-Erweiterung einmal in den Systemeinstellungen aktivieren. Das kann die App nicht heimlich für den Nutzer setzen, und das ist auch okay so. NewFileCreator führt durch den Schritt, aber der letzte Klick muss vom Nutzer kommen.

Zweitens entscheidet der Finder selbst, wo Erweiterungseinträge im Kontextmenü landen. Der New File-Eintrag steht deshalb nicht beim eingebauten Eintrag „Neuer Ordner“, sondern bei den anderen Erweiterungen. Das gibt macOS hier vor.

Für globale Shortcuts fragt macOS beim ersten Mal außerdem nach Automationsrechten für den Finder. Das muss man einmal erlauben. Danach sollten die Tastenkürzel ohne weiteres Nachfragen laufen.

Warum ich so etwas baue

Ich mag solche Projekte, weil der Umfang klar ist: ein störender Arbeitsschritt, eine Einschränkung in macOS und ein überschaubarer Weg darum herum. Kein großes Produkt, eher ein Werkzeug für genau diesen Moment.

Sowas spart natürlich keine Stunde am Stück. Es nimmt eher diese kurzen Unterbrechungen raus, die man irgendwann einfach akzeptiert. Genau das finde ich an KI-gestützter Softwareentwicklung praktisch: Das eigene System wird formbarer. Wenn mich ein Ablauf stört, muss ich ihn nicht immer nur hinnehmen. Ich kann ihn oft einfach ändern.

Der Code liegt auf GitHub, MIT-lizenziert, falls jemand das Tool selbst nutzen oder in den Code schauen möchte.
